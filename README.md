# Calculator Core & Infrastructure

C-калькулятор с REPL-интерфейсом, автоматическим препроцессингом выражений, стековым вычислителем ОПЗ, модульными тестами и еженедельным фаззингом по расписанию в CI.

## 🚀 Возможности и математические функции движка

Программа выполняет синтаксический разбор и вычисление инфиксных строк, поддерживая приоритеты, ассоциативность операторов и скобочные группы.

### 1. Поддерживаемые операторы и их приоритет (от высшего к низшему)
1. **Круглые скобки `( ... )`** — группировка и изоляция подвыражений.
2. **Функции** — `sin`, `cos`, `pow` и т.д. (вычисляются справа налево при вложенности).
3. **Унарный минус `-`** — изменение знака числа или выражения (например, `-5`, `-sin(x)`).
4. **Оператор степени `^`** — правоассоциативная операция (например, `2^3^2` вычисляется как `2^(3^2)`).
5. **Умножение `*` и Деление `/`** — левоассоциативные операции.
6. **Сложение `+` и Вычитание `-`** — левоассоциативные операции.

### 2. Спецификация встроенных функций
* `pow(база, степень)` или укороченный синоним `mypow` — возведение вещественного числа в степень.
* `nthroot(число, степень)` — извлечение корня произвольной степени $N$ из числа.
* `sin(x)` — вычисление синуса угла (аргумент $x$ передаётся строго в радианах).
* `cos(x)` — вычисление косинуса угла (аргумент $x$ передаётся в радианах).
* `tan(x)` (синоним `tg`) — вычисление тангенса угла.
* `cot(x)` (синоним `ctg`) — вычисление котангенса угла.
* `arcsin(x)` (синоним `asin`) — вычисление арксинуса (аргумент строго в диапазоне $[-1; 1]$).
* `arccos(x)` (синоним `acos`) — вычисление арккосинуса (аргумент строго в диапазоне $[-1; 1]$).
* `arctan(x)` (синоним `atan`) — вычисление арктангенса.
* `arccot(x)` (синоним `acot`) — вычисление арккотангенса.

### 3. Автоматический препроцессинг строк
Внутренний парсер текста выполняет предварительное форматирование строки перед токенизацией:
* **Игнорирование мусора:** автоматически удаляются все пробелы и символы табуляции.
* **Приведение регистра:** все символы приводятся к нижнему регистру (строка `SIN(COS(0))` преобразуется в `sin(cos(0))`).
* **Неявное умножение:** калькулятор сам расставляет пропущенные знаки умножения перед переменными, числами и скобками (конструкция `2A` превращается в `2*a`, `2(b+c)` в `2*(b+c)`, а `(a+b)(c+d)` в `(a+b)*(c+d)`).
* **Синонимы:** функции `tan`, `arctan`, `arccot` для совместимости с ОПЗ-ядром автоматически переводятся в системные токены `tg`, `atan`, `acot`.

### 4. Обработка ошибок и сингулярностей (Enum ErrorCode)
Ядро калькулятора не падает при некорректном вводе, а безопасно взводит коды ошибок:
* `ERR_OK` (код 0) — вычисление завершено успешно.
* `ERROR_PARSER_OPEN_PAREN_UNBALANCED` — обнаружена несбалансированная открывающая скобка (например, `((1+2)`).
* `ERROR_PARSER_CLOSE_PAREN_UNBALANCED` — обнаружена лишняя закрывающая скобка (например, `1+2)`).
* `ERROR_PARSER_MISSING_OPERAND` (код 4) — синтаксическая ошибка, нехватка операндов или неизвестный символ (например, пустые скобки `()`, одиночный оператор `*` или опечатка в имени функции).
* При делении на ноль (`1/0`) или в точках сингулярности тангенса (`tan(pi/2)`) калькулятор сохраняет математическую корректность, возвращая вещественное значение `INFINITY` или `-INFINITY` с учётом знаков операндов. При некорректных аргументах арксинуса (`arcsin(5)`) возвращается значение `NaN`.

## 🛠️ Архитектура ядра и этапы разработки

* **Алгоритм разбора:** Перевод инфиксной строки в Обратную польскую запись (ОПЗ) реализован по классическому алгоритму Сортировочной станции Дейкстры (Shunting-yard) с использованием динамического стека токенов.
* **Математическая стабилизация:** Реализована кастомная тригонометрия на рядах Тейлора. Для тригонометрических функций добавлена периодическая редукция аргументов к диапазону $[-\pi/4; \pi/4]$, что устраняет потерю точности double на больших числах. В циклы суммирования рядов зашит жесткий лимит на 100 итераций для защиты от бесконечных циклов.
* **Безопасность памяти:** Все структуры данных (динамические массивы, стек) защищены от порчи памяти при нехватке ОЗУ через промежуточные указатели при перевыделении (`realloc`), а ресурсы полностью освобождаются при любых синтаксических ошибках во вводе.

### История этапов разработки:
* **Этап 1:** Структуры данных и управление динамической памятью (Завершено) — Созданы базовые структуры для токенизации (`Token`), динамический стек операторов и очереди вывода.
* **Этап 2:** Лексический анализ и безопасность памяти (Завершено) — Написан лексер, разделяющий входную строку на числа, операторы и математические функции. Добавлен фикс DoS-зависаний лексера на некорректных точках (например, `2..3`).
* **Этап 3:** Синтаксический анализ и трансляция в ОПЗ (Завершено) — Интегрирован разбор скобок и приоритетов. Выровнен порядок извлечения операндов для функций с двумя аргументами (первым извлекается основание, вторым — степень/корень).
* **Этап 4:** Стабилизация вычислительного ядра и фикс багов (Завершено) — Исправлено вычисление арктангенса за счет деления аргумента пополам. Реализовано сохранение знаков `INFINITY` в тангенсах/котангенсах при делении на ноль на основе знаков синуса и косинуса.
* **Этап 5:** Автоматизация сборки и ультимативный контроль качества (Завершено) — Создан `Makefile` с автоматическим поиском исходников и генерацией файлов зависимостей (`-MMD -MP`). Интегрированы строгие флаги компилятора (`-Wall -Wextra -Werror -Wshadow -fstack-protector-strong`). Настроен Code Style под стандарт Google (`.clang-format`). Подключены статические проверки `cppcheck` и динамический поиск утечек памяти через `valgrind`.
* **Этап 6:** Пакетное тестирование и непрерывная верификация (Завершено) — Код тестов переведен на модульную структуру `TestSuite` по методике Data-Driven. Развернута и успешно пройдена матрица из 217 Unit-тестов. Написан шлюз для `libFuzzer` с seed-корпусом, который прогнал 31.8 млн мутаций без единого краша. Настроен GitHub Actions CI с разделением на быстрые проверки по коммитам и тяжелый cron-фаззинг по понедельникам.

## ⚙️ Инструкция по сборке, тестированию и запуску

Проект разработан и протестирован в окружении Linux (Arch Linux / Ubuntu). Для работы требуются утилиты: `make`, `gcc` (или `clang`), `valgrind`, `cppcheck`.

### 1. Сборка и запуск приложения (REPL)
Чтобы скомпилировать калькулятор в интерактивном режиме:
```bash
make
# или принудительно пересобрать проект целиком:
make clean && make
```
Запустить интерактивную консоль:
```bash
./calculator
```
В консоли можно вводить любые математические выражения. Выход из программы осуществляется вводом команды **`exit`**.

### 2. Запуск Unit-тестов
Прогнать всю матрицу из 217 встроенных тестов (арифметика, тригонометрия, парсер строк):
```bash
make test
```
*Команда скомпилирует тестовый бинарник и выведет статус по каждому тест-кейсу на экран.*

### 3. Статический и динамический анализ кода
Запустить статический анализатор `cppcheck` по всем папкам:
```bash
make check
```
Проверить Unit-тесты на утечки динамической памяти кучи через Valgrind:
```bash
make valgrind_test
```
*Критерий успешного прохождения: `All heap blocks were freed -- no leaks are possible`.*

### 4. Контроль стиля кода (Code Style)
Автоматически отформатировать весь проект под стандарт Google:
```bash
make format
```
Запустить проверку форматирования без изменения файлов (используется в CI):
```bash
make format-check
```

### 5. Локальный запуск фаззинга
Для сборки фазера и запуска стресс-тестирования ядра на основе мутаций из папки `fuzz/corpus` (длительность раунда ограничена 60 секундами):
```bash
make fuzz
```
*Результаты выполнения и логи фаззинга автоматически сохраняются в изолированную папку `logs/` с уникальным именем файла, содержащим дату и время запуска.*

### 6. Обновление дерева проекта в документации
Если в проект добавляются новые файлы, обновить структуру в этом `README.md` можно встроенным скриптом автоматизации:
```bash
make tree
```
